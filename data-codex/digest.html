Codex Docs Change Digest

2026-05-10 20:06 UTC

Executive Summary

Codex documentation expanded materially across the app, Windows, and extensibility surface. The May 10 refresh added 13 pages, removed 3 older pages, and rewrote key guidance around sandboxing, plugins, remote connections, memories, and subagents.

New Features

  • In-app browser docs now cover shared rendered-page preview, page comments, and Browser plugin driven browser use for local and public pages (browser)
  • Computer Use is now documented as a macOS GUI automation workflow with Screen Recording, Accessibility, and per-app approvals (computer-use)
  • Subagents now have first-class docs for built-in agents, custom agents, thread management, and concurrency/depth settings (subagents)
  • Plugins are now documented as the installable distribution unit for skills, apps, and MCP servers, with separate authoring guidance for marketplaces and packaging (plugins)
  • Memories are now documented as a feature with thread-level controls, storage details, and generation settings (memories)
  • Chronicle is now documented as an opt-in research preview that augments memories from screen context on macOS (chronicle)
  • SSH remote connections are now documented as an alpha Codex app feature for remote project execution (remote-connections)
  • Codex now documents an import flow for bringing setup, sessions, skills, hooks, MCP servers, and subagents from another agent into Codex (migrate)

Breaking Changes

  • Older multi-agent docs were removed in favor of the new subagent documentation, so bookmarks and internal links targeting multi-agent or concepts/multi-agents now need replacement (subagents)
  • The CLI reference no longer presents --full-auto as the primary path for edit-capable runs; the explicit replacement is --sandbox workspace-write --ask-for-approval on-request (cli-reference)
  • Windows guidance now states that WSL1 is unsupported starting in Codex 0.115, which matters for older Windows automation setups (windows)

Deprecations

  • codex exec --full-auto is now documented as a deprecated compatibility flag; new automation should switch to explicit sandbox flags (noninteractive)
  • on-failure remains documented as deprecated for approval behavior, with on-request or never preferred depending on interactivity (cli-reference)

Flag & API Changes

  • The CLI reference adds --remote and --remote-auth-token-env for connecting the interactive TUI to a remote app-server endpoint (cli-reference)
  • Sandboxing docs add deny-read filesystem profiles, granular approval policies, and automatic approval review via approvals_reviewer = "auto_review" (sandboxing)
  • MCP docs add experimental_environment = "remote" and remote-sourced env_vars entries for stdio servers that run in remote executor environments (mcp)
  • Auth docs add CODEX_CA_CERTIFICATE, a dedicated codex-login.log, and clearer billing guidance for ChatGPT sign-in versus API-key usage (auth)

Notable Clarifications

  • Quickstart now states that every ChatGPT plan includes Codex, and the Codex app is available on both macOS and Windows (quickstart)
  • IDE docs now treat Windows as a supported Codex IDE platform and clarify that VS Code opens Codex in the right sidebar by default (ide)
  • Skills docs now spell out the initial skill-list context budget and position plugins as the distribution layer for reusable skills (skills)

Action Items

  • Replace internal references and scripts that still use --full-auto, codex/explore, or legacy multi-agent URLs (noninteractive)
  • Review whether new browser, computer-use, memories, and Chronicle capabilities need policy guardrails before broad internal adoption (computer-use)
  • If you operate Windows, remote, or remote-MCP workflows, review the new sandbox and remote-environment settings before updating local defaults (windows)
